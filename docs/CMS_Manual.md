# Twin Assist CMS 初期版 操作マニュアル

## 画面とアカウント

本番設置後のURLは `https://独自ドメイン/admin/`。Cloudflare側の同じパスは読み取り専用のデザインプレビューです。保存可能な管理画面はPHP＋MySQL環境にあります。

管理者・編集者・問い合わせ担当を分け、個人ごとのアカウントを使います。共用パスワードは使いません。初期管理者作成と復旧は `CMS_Deployment.md` のCLI手順を利用。パスワードはここに記載しません。

- 管理者：全機能とアカウント管理。
- 編集者：在庫・カーストーリー・お知らせ・コラムの編集・公開。問い合わせの個人情報は閲覧不可。
- 問い合わせ担当：問い合わせの閲覧・担当・対応状況・社内メモ。公開コンテンツは編集不可。

右上に利用者名と役割を表示します。30分の無操作・12時間のログインで再認証します。パスワード変更時は別の既存セッションも無効になります。共有端末ではログアウトしてください。

## 在庫を登録する

1. 「在庫車」→「＋ 新規登録」。
2. タイトル、URL末尾、カテゴリ、販売状態、メーカー、車名、グレード、年式、走行距離、車検、修復歴、色、ミッションを入力。
3. 本体・諸費用・総額を**円**で入力。公開時に本体＋諸費用＝総額を検証。価格の適用条件も入力します。
4. 装備マークは「未確認・装備あり・装備なし」を選択。ありはカラー、なしは白黒、未確認は非表示です。
5. 本文に車両の説明を入力。
6. ページ下部「新しい画像を登録」で画像と説明をアップロード。画像一覧から選択し、上下ボタンで掲載順を変更。先頭が一覧画像です。
7. 「下書き保存」→「下書きをプレビュー」で表示を確認。
8. 検索結果用の説明、事実・権利・許諾の確認を入力し、「公開する」を押します。
9. 「公開ページを見る」で確認。販売状態を変更したときも「変更を公開」で反映します。

写真はJPEG・PNG・WebP、8MB以下、各辺6000px以下、2000万画素以下、20枚まで。SVGやスクリプト等は登録できません。ナンバーや顔、他人の情報の写り込みと掲載権利を確認してください。

公開中の内容を編集して「下書き保存」しても、公開ページは変わりません。「変更を公開」で切り替えます。公開履歴があるURLは破損リンクを避けるため変更できません。他の人が先に更新した場合は競合を表示するので、保存前の内容を手元で確認し、再読み込みして調整します。

「公開を停止する」で公開ページとサイトマップから除外。非公開の在庫は「ごみ箱へ移動」でき、一覧のごみ箱から復元できます。復元だけでは再公開されません。

## 記事・コラムを投稿する

1. 「カーストーリー」「お知らせ」「コラム」のいずれか→「新規登録」。
2. タイトル、URL、カテゴリ、紹介文、本文、写真を入力。著者は実在する担当者等を必要な場合だけ入力。
3. 本文は `## 見出し`、`### 小見出し`、`- 箇条書き`、`[リンクの文字](/stock/)` を使用できます。空行で段落を区切ります。HTMLはそのまま実行されません。
4. 関連記事は管理一覧のIDをカンマ区切りで指定。公開中の記事だけを表示します。
5. SEOタイトル・説明文を設定し、下書き→プレビュー→公開。
6. 実体験談・写真は許諾を確認。サンプル・架空の場合はサンプル設定をオンにします。

本番の検索公開設定が有効で、公開中・検索対象指定あり・サンプルではないページがサイトマップに載ります。新記事ごとのSearch Consoleへのサイトマップ再登録は不要です。Googleへの登録や順位は保証されません。

## 問い合わせに対応する

1. 「問い合わせ」から「未対応」を確認し、受付番号の詳細へ。
2. ご相談内容・対象車両・連絡先を確認。通知メールが来ていなくても一覧を確認します。
3. 担当者・対応状況・必要最小限の社内メモを入力し「対応状況を保存」。
4. 完了後は「完了」にします。完了は予約・契約の自動成立ではありません。
5. 社内の保存期間と法令・対応上の必要性を確認し、不要になった完了データは管理者が「完全削除」。元には戻せません。バックアップ中の保持も別途管理します。

通知状態 `pending` は待機、`processing` は処理中、`accepted` は配送処理の受付、`failed` は失敗です。メール配達そのものの証明ではありません。宛先・配送設定・cronが未設定なら通知されません。通知設定前でも受付を有効化するとDBへは保存されるため、本番では運用を確定してから受付を開始します。

## 本番前に確定する項目

正式な会社情報・電話・LINE・ドメイン、古物商許可、法務ページ、フォーム受付先、メールの実配達、問い合わせの保存期間・削除担当、バックアップ頻度と復元手順。開発中は全体のBasic認証とnoindexを維持します。

今回の初期版に予約公開・MFA・CSV出力・会社情報等のGUI編集は含みません。一般ページは既存デザインのコードとして管理し、機密設定は管理画面の入力欄ではなくサーバーの非公開設定で管理します。

## 追加：装備65項目・地域タグ・SEO/AIOの編集

- 装備は6分類65項目。各項目を「未確認・装備あり・装備なし」で選択します。未確認の項目は公開しません。既存の装備の有無は保持され、新しい項目を自動で「なし」にしません。
- 在庫・コラムの新規入力は「大正・大正区の方向け」を地域候補として初期選択します。所在地や実際の対応可能地域を断定する設定ではありません。不要な記事では地域指定を外します。
- 自動タグはタイトル・本文・紹介文・カテゴリ・要点に基づいて補完。タイトルの主題を優先し、地域×内容の組み合わせを作成。手動タグと合わせて重複を除き24件まで。自動補完をオフにもできます。全記事に同じ全キーワードを埋め込む方式ではありません。
- タグは公開ページに表示され、同じ種類のタグで記事・在庫一覧を絞れます。タグ絞り込み一覧はnoindex。新しい地域名の薄いページを大量生成しません。
- 手動の関連記事指定がない場合、共通する内容タグから関連記事を最大3件補完します。地域名だけの一致では関連記事にしません。非公開の記事を候補に含めません。
- 「この記事・車両の要点」「確認ポイント」「FAQ」「参考資料・出典」「内容確認日」を入力できます。実際に確認した内容と資料だけを記載。FAQは8件、参考資料は10件、確認ポイントは5件まで。参考URLはhttp/httpsのみです。
- 公開ページの要点・FAQ・出典・確認日をHTML表示。Article、BreadcrumbList、実際に表示するFAQの構造化データを生成。著者は記入した場合のみ、所在地は推測して出力しません。
- AIO（AI検索への情報提供）やSEOの技術的な土台であり、AIへの採用・引用、Googleのインデックス・順位、FAQのリッチリザルトを保証しません。meta keywordsの大量設定は行いません。
