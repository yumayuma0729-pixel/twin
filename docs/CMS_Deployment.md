# Twin Assist 独自CMS：開発・エックスサーバー設置

## 今回の実装範囲

PHP 8.2以上（開発検証8.3）＋PDO MySQL＋MySQL/MariaDB。ComposerやNode.jsは本番実行に不要です。管理画面は `/admin/`。在庫、カーストーリー、お知らせ、コラム、問い合わせ、アカウントの管理を実装しています。

**Cloudflareの静的プレビューと、保存できるPHP版は別です。** `public/admin/` は読み取り専用のデザインプレビューです。CloudflareへPHPや秘密設定・DB・問い合わせデータは配信しません。PHP実装は `cms/` にあり、公開静的ディレクトリ外です。

まだエックスサーバーの実機検証、独自ドメイン、Basic認証、正式な個人情報運用、実メール配達の設定・確認は行っていません。予約公開、MFA、メールによるパスワード再設定、問い合わせのCSV出力、一般ページ/会社設定の編集は今回の範囲外です。本文編集は安全な簡易Markdown（見出し・箇条書き・リンク・段落）と画像順序の管理です。WYSIWYGエディタではありません。

## この開発環境

```
cd /workspace/twin
./scripts/start-cms.sh
```

- Dockerが必要。PHP＋MariaDBを起動し、DBを初期化、HTTPのログイン画面まで確認します。
- PHPアプリのローカルポートは8080、DBのホスト側公開ポートはありません。
- DBパスワード・認証キーは `cms/dev/.env` に初回だけランダム生成。Git対象外です。再生成すると既存DBの認証と合わなくなるため、稼働後に勝手に削除しないでください。
- 開発DB・画像・設定の秘密値をGitに入れないでください。
- 初期管理者は固定パスワードを持ちません。以下はメール・氏名を実際の担当者に置き換えます。パスワードは14〜72バイトで、権限600の一時ファイル等から標準入力で渡します。コマンド引数やチャットに書きません。

```
DOCKER_CONFIG=/tmp/twin-docker-config docker compose -p twin-cms -f cms/dev/compose.yaml \
  exec -T app php bin/console.php user:create YOUR_EMAIL YOUR_NAME admin < /PRIVATE/PASSWORD_FILE
```

作成後は一時パスワードファイルを安全に削除し、管理画面のパスワード変更を利用します。メール配送は別設定です。ログイン名としてのメール登録だけではメール送信は開始しません。

## エックスサーバー用パッケージ

```
python3 scripts/package-xserver.py
```

`dist/twin-assist-xserver.zip` を生成します。開発DB、local.php、.env、アップロード済み画像、ログ・バックアップを含めません。既存の静的デザイン資産とPHPコード、設定例、DB初期化SQL、マニュアルを同梱します。

配置例（実際のサーバーアカウント・ドメインに合わせる）：

```
/home/ACCOUNT/DOMAIN/
  public_html/          ← 公開HTML/CSS/画像＋index.phpと.htaccess
  twin-cms/             ← 非公開（public_htmlの外）
    app/
    bin/
    config/local.php
    database/
    storage/media/
```

1. サブドメインまたは本番予定ドメインを作成し、SSLを有効化。開発中はエックスサーバーのアクセス制限機能でサイト全体にBasic認証を設定します。管理画面自身のログインはこれと別です。
2. 管理パネルでPHPの対応版とPDO MySQL・Fileinfo・getimagesizeの利用可否を確認。PHP 8.2以上を選びます。アップロード上限はPHP側も8MB以上、post_max_sizeは余裕を持たせます。アプリ側は8MB・JPEG/PNG/WebP・各辺6000px/2000万画素以下に制限。
3. MySQL/MariaDBのデータベースと専用ユーザーを作成します。アプリは自DBの必要な権限のみ。DB作成権限やサーバー全体の権限は与えません。
4. パッケージの `public_html` と `twin-cms` を上記の位置へ配置。`public_html/index.php` が非公開 `twin-cms/app/bootstrap.php` を参照していることを確認します。既存のBasic認証設定は消さず、`.htaccess` のCMSルールと統合してください。
5. `twin-cms/config/example.php` を同じ非公開ディレクトリ内の `local.php` としてコピーし、正式なURL、DB、画像保存先を設定。`auth_key` はサーバーで `bin2hex(random_bytes(32))` により生成します。設定ファイルは所有者だけが読める権限を基本とします。
6. `site_root` は実際の `public_html`、`media_root` は非公開の `twin-cms/storage/media` を指定。画像ディレクトリを作り、PHPの実行ユーザーだけが書ける権限にします。画像はPHP経由で配信され、非公開記事の画像はログイン権限なしで取得できません。
7. SSHで `php twin-cms/bin/console.php migrate` を実行し、管理者を標準入力パスワードで個別作成。公開セットアップURLはありません。
8. 在庫1台・記事1本で下書き、プレビュー、公開、変更の下書き、公開停止、画像順序、装備、権限を実機確認。PHP開発サーバーは本番では使いません。

## 問い合わせとメール

初期値は `inquiries_enabled=false`、`mail_enabled=false`。この状態では入力・確認までで、受付保存・送信はできません。

実受付開始前に、正式な窓口・プライバシーポリシー・保存期間・バックアップの扱い・削除担当・スパム運用を確定。`inquiries_enabled=true` で公開フォームと右サイドフォームが確認→明示送信→DB保存になります。問い合わせは保存を完了してから完了画面へ移ります。来店予約の確定ではありません。

通知先 `notification_to`、所有・設定済みドメインの差出人 `notification_from` と配送設定を確定して `mail_enabled=true` にします。通知本文は受付IDと管理画面への案内にとどめ、お客様の本文・連絡先をメールへ転記しません。

```
php /PRIVATE/twin-cms/bin/console.php notify
```

このCLIをサーバーのcron等で実行。未設定なら送信せず受付データを保持します。配送処理の失敗は再試行（最大5回）し、状態は管理画面に表示。`accepted` はPHP mail()が処理を受け付けた状態で、メール配達の保証ではありません。SPF/DKIM/DMARC、実際の受信、迷惑メール振分けを確認します。5回失敗後の再開は運用者による原因修正・状態確認が必要です。

公開フォームにはCSRF、確認画面、ハニーポット、最低入力時間、IP単位の頻度制限、一意キーによる二重受付防止を入れています。本番負荷・スパム状況に応じてWAF等の追加対策を検討してください。

## SEO・サイトマップ

`indexing_enabled=false` が初期値。管理・下書き・プレビューは常にnoindexです。開発ではrobotsもDisallow: /。

本番URL、Basic認証解除、実コンテンツ・権利・法務情報の確認後に `indexing_enabled=true` とします。公開済み・検索対象指定あり・サンプルではないCMS詳細ページだけを `/sitemap.xml` に動的出力します。公開/更新/公開停止の変更は次の取得時に反映され、再登録は不要です。Googleのクロール・インデックス時期は保証しません。Indexing APIへの送信は行いません。

静的ページとCMS一覧ページの検索公開は今回は安全側のnoindexを維持しています。本番では個別に内容・canonical等を確認して検索対象へ切り替えます。サンプル、法務の未確定情報を含むページを自動でindexにしません。

## バックアップ・移行

移行対象は **DB、非公開アップロード画像、コード・静的資産、秘密設定**。GitHubはDB・アップロード写真のバックアップにはなりません。

- 日次などの頻度・世代数・保管先・暗号化・保存期間は本番前に決定。エックスサーバーの自動バックアップの契約時点の対象・復元条件も確認します。
- 更新や移行前には別途バックアップ。DBは整合性のあるダンプ、画像は同じ時点の保存を確保。
- `python3 scripts/backup-cms-dev.py` はローカル開発用のDB・画像バックアップを `cms/storage/backups` に作ります。秘密設定は含めないので別途安全に保管します。
- 実機で別DBへ復元し、件数・画像・ログイン・公開/非公開・問い合わせを確認。作成できたことだけで復元可能とは扱いません。
- 本番では開発用テストアカウント・テスト投稿・テスト問い合わせを移行しません。パッケージはそれらのデータを含みません。

## 検証

`tests/cms-integration.cjs` はlocalhostの使い捨て開発データ向けです。本番URLでは実行を拒否します。テストアカウント情報はGit外のファイルで指定します。実際の顧客情報は使いません。`app-test` profileは検索・受付を有効にしたローカル検証用で、通常起動では有効にしません。

認証・CSRF・権限、画像の非公開保護、不正画像拒否、下書き分離、価格検証、競合検知、公開/停止/ごみ箱、SEOとエスケープ、サイトマップ対象制御、問い合わせの明示送信・重複防止・通知キュー・対応状況、スマホレイアウトを確認しています。実メール配達とエックスサーバー固有の設定は未検証です。

## 追加：タグ・構造化データと既存ページ

装備・トピックの共通定義は `public/data/cms-catalog.json`。CMSのJSON保存項目を追加しており、既存レコードの破壊的なDB移行は不要です。旧レコードを新しい「装備なし」や地域指定ありとみなしません。

`python3 scripts/refresh-static-topics.py` は既存サービス・在庫・コラム等へ文脈に合う可視タグを生成します。法務・プライバシー等へ無関係な地域キーワードは付けません。既存コラムはArticle、サービス等はパンくず、TOPは実際のFAQ内容を構造化します。現在のプレビューURLを使用するため、本番前に `--base-url https://正式ドメイン` を指定し、静的ページの正規URL・内容を合わせて確認してください。

通常のCMSページの正規URL・構造化データは `base_url` から生成。サンプル・下書きのnoindexと、開発環境の検索公開停止は維持されます。robotsでAIクローラーだけ特別に開放する設定はしていません。
