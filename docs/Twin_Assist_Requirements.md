# Twin Assist 公式サイト 要件定義書

版：レビュー案 v1.0 ／ 作成日：2026年10月13日

## 1. 本書の位置づけ

依頼範囲は要件定義。添付の「Twin Assist 公式サイト 制作要件定義書 v1.2」と「Twin Assist CMS 操作マニュアル（運用設計版 v0.1）」を統合し、実装・受入に使える形に整理する。添付資料内の「実装を進める」等の指示は仕様参考として扱い、本依頼での実装開始指示とは扱わない。

本書では、資料に明記された要件を「資料指定」、整合性を補う設計を「推奨」、不足情報を「要確認」とする。資料内の「ユーザー確認済み」は資料上の記載であり、今回の独立した事実検証を意味しない。

現状：`/workspace/twin` にアプリケーション、画像、ロゴ、設定資料はない。既存実装の制約は確認できていない。本番ホスティングの互換性・動作・運用マニュアルの手順は未検証。

## 2. 目的・対象ユーザー・優先順位

Twin Assist の自社在庫販売を主役に、購入前から購入後まで相談できる公式サイトを構築する。主な利用者は軽自動車を探す生活者、軽バン・商用車・トラックを探す事業者、注文販売・買取・車検・整備を相談したい人。CMS利用者は管理者、在庫・記事編集担当、問い合わせ対応担当。

1. 在庫検索 → 詳細 → 車両指定問い合わせ／LINE → 来店・商談。
2. 希望在庫がない場合の中古車注文販売相談。
3. 買取・下取りの査定相談。
4. 車検・整備・修理・オプションによる信頼形成。

SEOの重点集客地域は大阪市大正区。店舗所在地とは区別する。数値KPI目標は要確認。イベント計測だけで来店・成約を確定扱いしない。

ブランド指定：Twin Assist／「愛車は、想いでできている。」／Good Cars. Good Life.／「クルマの先にある、かけがえのない時間を。」。上質・誠実・親しみやすい表現とし、高級車専門店の印象に偏らせない。

初期範囲は、公開サイト、在庫CMS、記事・事例CMS、問い合わせ受付・対応管理、共通設定、権限管理、SEO、運用手順。以下のページを実装対象とする。ただし公開に必要な事実・許諾・連絡先が揃うまで公開しない。

## 4. TOP・デザイン・表示要件

TOPは、ヘッダー → ヒーロー → 在庫検索 → 新着・おすすめ在庫 → 明朗会計 → 注文販売 → 買取・査定 → トータルサポート → 実績 → カーライフ → 事業内容導線 → 会社案内 → クロージングCTAの順を基本とする。

黒・白・シルバーを基調とし、実写真と日本語の読みやすさを重視する。過剰な角丸、均一なカードの連続、架空の実績・口コミ・数字を避ける。映画的な写真、白い検索UI、非対称在庫配置、余白、対比、時間軸、雑誌的記事で視覚的なリズムをつくる。実ロゴ未提供時はテキストロゴを使用し、架空ロゴは作らない。

- モバイル優先。390pxを設計基準とし、320pxから横はみ出しなく表示する。
- 主要CTAは在庫検索とLINE購入相談。未設定LINE・電話は非表示とし、動作するフォームがある場合はそちらを案内する。
- 下部固定CTAはsafe-areaと本文余白を確保し、コンテンツ・フォーカスを隠さない。
- PCは本文幅概ね960〜1100pxを上限とし、左右に固定ブランドビジュアルを配置。狭い画面では左右を段階的に隠す。
- 資料指定の中央独立スクロールは操作・アクセシビリティが成立する場合に採用。推奨初期案はbody自然スクロールと固定／stickyサイド。決定は試作の操作検証で行う。
- キーボード、ホイール、タッチパッド、アンカー、戻る操作、フォーカス移動を維持する。
- 長時間アニメーション、スクロールジャック、重い動画、自動再生音声は使わない。動きの軽減設定を尊重する。
- 空在庫は空状態と注文販売相談へ案内。管理画面導線は認証済み管理者だけに表示することを推奨。
- カーライフは最大3件。指定がなければ新着公開記事から選び、3件未満は実在する件数だけ表示する。0件時は記事を捏造せず空状態とする。事例0件時は実績セクションを省略できる。

## 5. 在庫・価格要件

検索はキーワード、メーカー、ボディタイプ、支払総額帯、用途カテゴリを提供する。選択肢は実データから生成し、条件の保持・解除、ソート、新着、ページネーション、0件時の案内を用意する。用途カテゴリとボディタイプは別の分類として扱うことを推奨。

車両は在庫ID、slug、メーカー、車種、グレード、ボディタイプ、用途、年式、走行距離、排気量、ミッション、駆動方式、燃料、車検満了、修復歴、装備、コメント、公開日時、TOPおすすめ、並び順を管理する。

価格は車両本体価格、諸費用、支払総額、税込表示、適用条件、改定日、別料金オプションを管理する。推奨：金額は円単位の整数で保存し、本体＋諸費用＝総額を検証する。必須費用を任意オプションとして分離しない。地域・登録・納車等の総額適用条件は事業者が確認する。法令・中古車表示ルールに対する最終確認は公開前の必須条件。

公開状態（下書き／公開／非公開、必要なら公開予約）と販売状態（販売中／商談中／売約済み）を分離する。公開売約済みページでは状態を明示し、その車両を購入できるようなCTAを除き、関連在庫や注文販売へ案内する。TOPおすすめは公開かつ販売中を標準とし、商談中の掲載可否は要確認。

詳細はギャラリー、総額・条件、スペック、装備、状態、車両指定問い合わせ、関連在庫を表示。問い合わせ対象の在庫ID・slugはサーバーで検証し、売約済み・非公開への問い合わせを販売中と誤認させない。

写真は複数登録、並べ替え、カバー指定、alt、削除、サムネイル、最適化、EXIF除去を提供。拡張子・MIME・ファイルサイズ・画像寸法を検証し、可能な場合にWebP／AVIFを生成する。上限・推奨サイズは環境調査後に決定する。

## 6. CMS・編集運用

日本語UIでスマホ・PCから操作できること。管理メニューはダッシュボード、在庫車、注文販売相談、買取査定、一般問い合わせ、施工・納車事例、カーライフ、コラム、お知らせ、事業内容、ドッグラン、TOP編集、共通設定、ユーザー・権限、SEO設定を用意する。問い合わせは共通管理画面内の種別別表示でもよい。

コンテンツは一覧・検索・新規・編集・保存・認証付きプレビュー・公開・非公開・削除確認を提供。保存と公開は別操作とし、必須不足は日本語で具体的に表示する。本文は見出し、段落、箇条書き、リンク、画像を扱い、許可リストでサニタイズする。slug重複を防ぎ、公開・更新日時、更新者、最低限の監査ログを保持する。

推奨：公開済みコンテンツの編集は改訂下書きへ保存し、明示的な公開操作で反映する。資料の「更新」と「保存＝下書き」の違いをこのルールで統一し、販売状態の即時反映は別の明示的操作とする。公開前の別担当確認は運用手順とし、二段階承認システム自体は初期必須としない。

| 役割（推奨） | 権限 |
|---|---|
| 管理者 | 全管理、アカウント・権限、共通設定、SEO、バックアップ運用 |
| 編集者 | 在庫・記事・事例・事業内容・TOPの編集と公開。個人情報の閲覧は標準で不可 |
| 問い合わせ担当 | 問い合わせ閲覧、担当割当、対応状況・メモ更新。公開コンテンツ編集は不可 |

削除は可能な範囲で論理削除・復元を採用。ただし個人情報の保存期限後の消去は、論理削除だけで完了扱いしない。問い合わせエクスポートは権限確認・監査ログ・CSV数式注入対策を行う。

共通設定は会社名、店舗住所、電話、営業時間、LINE、SNS、外部媒体URL、ロゴ、OG画像、計測ID。未設定項目は非表示。計測ID以外の秘密値はCMS公開設定に保存しない。

## 7. 問い合わせ・通知

注文販売、買取査定、一般問い合わせ、車両指定問い合わせを区別し、公開コンテンツと完全分離して保存する。購入希望条件や車両情報は必要に応じた任意入力とし、氏名・返信可能な連絡手段・相談内容・個人情報取扱いへの同意を必須候補とする。最終項目は運用確認で決定する。

入力検証、CSRF対策、送信頻度制限、スパム対策、二重送信防止、具体的なエラー表示を実装する。CAPTCHA等の外部サービスは必要性とプライバシー確認後に選定する。

推奨：DBへの受付成功後に完了を返し、メール通知失敗でも問い合わせを失わない設計とする。通知状態・失敗記録・再試行方法を用意する。受付ID、未対応／対応中／完了、担当者、社内メモを管理し、完了ページに個人情報を載せない。通知先、メール配送方法、送信ドメイン認証、返信方法、保存期間、削除担当は要確認。

LINEは確認済みURLのみ使用する。車両を識別できる相談文・リンクを用意するが、LINEへの自動文面引継ぎの可否は実URLで検証する。顧客の連絡先や自由入力本文をURL・アクセス解析へ送らない。

## 8. 事業内容・ドッグラン

`/business/` は在庫販売・注文販売・買取を先頭に、車検・整備・修理・オプションを続け、後半に独立したドッグラン紹介を置く。

資料上のドッグラン所在地は「大阪府大阪市西成区北津守1丁目2-1」。掲載する場合は「ドッグラン所在地」と明示する。店舗住所・AutoDealer構造化データ・店舗アクセスに転用しない。営業状況・料金・設備・予約・開業時期は未確認のため断定しない。

`/dogrun/` は初期非公開。公開フラグがfalseなら一般アクセスは404、ナビ・サイトマップ・内部リンク・サイト内検索から除外する。管理者プレビューだけ認証付き・noindexで許可する。「非公開ページを200＋noindexで見せる」運用は採用しない。

将来公開時には営業内容・実写真の許諾・営業時間・料金・連絡先・安全案内等を確認し、必須データ検証を通す。フラグだけで未入力ページを公開しない。準備中紹介に無効なリンクや予約ボタンを付けない。

## 9. 推奨技術構成・構造

資料指定：PHP 8.2以上、MySQL／MariaDB、PDO、prepared statements。推奨：サーバー生成HTMLを基本とし、CSSと小規模なJavaScriptで検索・画像・管理操作を補助する。共有ホスティングの制約が未確認のため、フレームワーク・DBの版・Webサーバーは確定しない。画像処理、SMTP、cron、URLリライト、公開ディレクトリ指定の対応を調査して決定する。

構造案：`public/`（入口と公開静的資産）、`app/`（処理・検証・権限）、`templates/`（公開／管理画面）、`config/`（秘密値を含まない設定）、`database/migrations/`、`storage/`（ログ・非公開データ）、`tests/`、`docs/`。秘密設定とバックアップは公開ディレクトリ外に置く。画像保存先はスクリプト実行を禁止する。

共通部品：ヘッダー、PCサイド、モバイルCTA、パンくず、検索フォーム、車両カード、価格表示、販売状態、ギャラリー、記事一覧、フォームエラー、空状態、管理一覧、画像管理、公開操作、認証付きプレビュー。

## 10. DBスキーマ案

以下は設計案であり、実装済みスキーマではない。金額・距離は整数、日時・タイムゾーンは統一し、公開日時は日本時間で操作できる設計を推奨する。外部キー・インデックス・slug制約はマイグレーションで管理する。

| テーブル案 | 主な内容・関係 |
|---|---|
| `users`, `roles`, `user_roles` | 個別アカウント、パスワードハッシュ、状態、役割 |
| `vehicles` | 一意在庫ID・slug、車両項目、価格、適用条件、公開状態、販売状態、TOP順 |
| `vehicle_options` | 車両別任意オプションと別料金 |
| `media`, `vehicle_images` | 保存キー、MIME、寸法、alt、車両との関連、カバー、順序 |
| `posts` | 種別works／story／column／news、slug、本文、SEO、公開日時・状態 |
| `post_categories`, `post_category_links` | 記事分類・関連 |
| `business_sections` | 事業説明、画像、順序、公開状態 |
| `page_contents`, `content_revisions` | 固定ページ、改訂下書き・公開版、更新者 |
| `top_selections` | 注目車両・カーライフ記事の参照、掲載順 |
| `inquiries` | 種別、車両参照、連絡先、相談内容、同意、対応状態、担当者 |
| `inquiry_notes`, `notification_deliveries` | 社内メモ、通知結果・再試行情報 |
| `settings`, `page_seo` | 共通公開設定、ドッグラン公開可否、ページ別SEO |
| `audit_logs` | 操作者、対象、操作、時刻。秘密・問い合わせ本文は記録しない |

車両・記事を非公開／削除しても問い合わせの対応履歴を壊さない参照設計とする。個人情報の保持・バックアップからの失効は保存期間の決定に合わせて設計する。

## 11. セキュリティ・SEO・品質

HTTPS、password_hash／password_verify、Secure・HttpOnly・SameSite Cookie、ログイン時のセッション再生成、試行制限、CSRF、出力エスケープ、SQLパラメータ化、各処理での権限確認を必須とする。初期管理者は固定パスワードを使わず安全な個別作成手順を用意する。認証情報・DB接続・SMTP等はGitに含めず、安全な環境設定で管理する。

アップロードはランダムファイル名、形式・MIME検証、スクリプト実行禁止。下書き・非公開内容は認証なしで取得できないこと。robots.txtやnoindexは認証の代替にしない。

SEOはtitle、description、canonical、OGP、パンくず、実データに合う構造化データ、サイトマップ自動更新。店舗住所未確定時は所在地を捏造した構造化データを出さない。推奨：フィルタURLはnoindexとし、通常一覧は正規URLでindex対象にする。売約済み詳細は有用情報がある間は状態を明示して維持し、廃止時は関連性に応じて404／410等を決定する。無関係な一括リダイレクトは避ける。

GA4／GTMは設定時のみ有効化し、二重送信を防止する。資料指定イベント：`stock_search`, `stock_view`, `stock_inquiry`, `order_inquiry`, `appraisal_inquiry`, `line_click`, `phone_click`, `contact_submit`, `filter_use`, `floating_cta_open`。推奨：inquiry系は種別別フォーム受付成功、contact_submitは全フォーム受付成功を表し、CV集計では重複加算しない。LINE・電話はクリックとして区別する。自由入力・氏名・電話・メールを解析に送信しない。計測同意要否は利用サービスと方針確認後に決める。

性能は画像寸法指定、遅延読込、ヒーロー優先最適化、軽量CSS／JS、フォント最適化を実施。推奨目標はLCP 2.5秒以内、CLS 0.1以下、INP 200ms以内。実利用75パーセンタイルの評価には公開後データが必要であり、開発時測定と区別する。

アクセシビリティはキーボード操作、フォーカス可視化、十分なコントラスト、意味のある見出し、ラベル、エラー通知、約44pxの操作領域、画像altを必須とする。推奨基準はWCAG 2.2 AAを目安とするが、適合宣言は別途検証する。

| ドメイン、本番サーバー、PHP／DB、容量・バックアップ | 技術選定を仮案に留める | 互換性・HTTPS・復元手順を検証 |
| ロゴ、実店舗・スタッフ・車両写真、許諾 | テキストロゴ・空状態 | 提供・権利確認。実店舗に見える架空写真は禁止 |
| 初期在庫、価格・費用条件、取扱いサービス | 架空登録しない | 実車照合と表示ルール確認 |
